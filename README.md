# Inside Motion Study

这是一个 React + TypeScript + Vite 的纯 WebGL2 视觉原型，用来测试“手机左右倾斜时，屏幕 UI 以一侧边缘为铰链反向旋转，并向屏幕内部下沉、逐渐失焦”的效果。只使用绕屏幕竖轴的旋转，前后倾斜和面内旋转不会单独改变画面。它使用 `DeviceOrientation` 读取真实手机姿态，也提供手动模拟；这不是头部追踪系统。

## 在线体验与部署

- 在线地址：[INSIDE](https://amasun.github.io/iphoneduo/)
- 源码仓库：[amasun/iphoneduo](https://github.com/amasun/iphoneduo)

在线版本由 GitHub Pages 提供受信任的 HTTPS，无需连接开发电脑的 Wi-Fi 或安装本地证书。iPhone Safari 打开后，双击显示操作界面，启用手机体感并允许方向访问；也可添加到主屏幕后打开。

推送到 `main` 后，GitHub Actions 会使用 Node.js 24 与项目指定版本的 pnpm 安装依赖、运行测试、构建并发布 `dist`。Pages 使用 GitHub Actions 作为部署来源。生产资源使用 `/iphoneduo/` 前缀，PWA 启动地址和作用域也跟随项目路径；本地开发仍从 `/` 访问。部署不需要额外配置密钥。

## 本地启动

在项目目录执行：

建议使用 Node.js 24 与 pnpm。

```bash
pnpm install
pnpm dev
```

桌面浏览器可打开 `http://localhost:5188/`。同一 Wi-Fi 下，手机 Safari 可以访问电脑的局域网地址，例如当前示例：

```text
http://192.168.1.10:5188/
```

`192.168.1.10` 只是本机当前示例，实际地址以电脑网络适配器显示的 IPv4 为准；可用 `ipconfig` 查看。电脑防火墙需要允许 Node/Vite 监听 5188 端口。

普通 HTTP 地址适合查看视觉和手动模拟。iPhone Safari 的方向传感器需要受信任的 HTTPS 环境；局域网 HTTP 页面不应当作为体感测试地址。

## iPhone HTTPS

本机已使用 mkcert 配置本地受信任证书，覆盖 `localhost`、`127.0.0.1`、`::1` 和 `192.168.1.10`。网站证书有效期至 2028-12-11。网站证书和私钥保存在已忽略的 `certs/`；根 CA 私钥由 mkcert 保存在系统用户目录中。

启动 `pnpm dev:https` 后，体验地址为 `https://192.168.1.10:5188/`。另外在一个终端运行 `pnpm dev:cert`，iPhone Safari 可打开 `http://192.168.1.10:5189/` 下载公开的根证书并查看安装步骤。证书下载服务仅提供说明页和 `inside-local-ca.cer`，不会开放任何目录或私钥。首次在 iPhone 安装后，还需要在「设置 → 通用 → 关于本机 → 证书信任设置」中开启完全信任。

先停止原来的 HTTP 开发服务，再启动 HTTPS 服务（两者默认使用同一个端口）。

```bash
pnpm dev:https
```

没有本地证书时，这个命令使用 Vite 的自签名证书。它可以用于查看页面，但 iOS 是否信任该证书、以及方向权限是否可用，都不保证。正式测试建议使用受信任的 HTTPS 证书。

项目已经支持以下证书文件：

```text
certs/dev.pem
certs/dev-key.pem
```

两者同时存在时，Vite 会直接读取它们；`certs/` 已被 `.gitignore` 忽略。可以用 `mkcert` 为本机地址生成证书：

```bash
mkcert -install
mkdir certs
mkcert -cert-file certs/dev.pem -key-file certs/dev-key.pem localhost 127.0.0.1 192.168.1.10
pnpm dev:https
```

如果局域网 IPv4 变化，需要用新的地址重新生成证书。为了让 iPhone 信任这套本地 CA，把 `mkcert` 生成的 `rootCA.pem` 传到 iPhone 并安装，然后在“设置 > 通用 > 关于本机 > 证书信任设置”中打开对该根证书的完全信任。只安装 `rootCA.pem`，绝不要把 `rootCA-key.pem` 传到手机或提交到仓库；证书私钥也不要提交。

## iPhone 操作

手机打开页面会自动进入沉浸模式，横屏打开也支持。默认只显示画面，双击画面显示操作界面，再次双击收起。显示后，右上角可打开效果调节，左上角可退出沉浸模式；电脑切换到手机尺寸预览时也会自动进入。单击、拖动、长按与双指操作不会触发界面切换。

沉浸画布覆盖浏览器允许绘制的完整区域，操作界面跟随可见视口，主屏幕 Web App 使用相同布局。背景按等比铺满、顶部对齐显示，屏幕较矮时优先保留原图顶部，将超出的下方内容裁掉；较窄时允许从左右裁切，不拉伸。转动时不会为了容纳整张图片而整体缩小，固定侧整条边保持贴屏，超出屏幕的内容由物理屏幕边界裁切。

全屏布局参考了 [Solo](https://solotilt.com/) 的视口处理：`html`、`body` 与画布都使用完整的大视口高度，画布直接固定到视口，安全区仅给操作控件留距离。此前只有固定定位的内部容器撑满，`body` 实测高度为 0；现在文档本身也覆盖画面，并移除沉浸模式继承的桌面 3D 容器。页面恢复、切回前台和尺寸变化都会更新视口位置。

主屏幕清单声明 `fullscreen`，同时保留 iOS 的 `black-translucent` 与 `viewport-fit=cover` 设置。iOS 会缓存已添加的 Web App 启动信息；更新后请删除旧的 INSIDE 主屏幕图标，在 Safari 重新打开 HTTPS 首页，再通过“添加到主屏幕”添加，若出现“作为 Web App 打开”选项则保持开启。仅刷新旧图标内的页面可能不会更新启动模式。

页面不再指定深黑色的浏览器主题，并用原图和灰蓝色背景填充可绘制区域。Safari 地址栏和工具栏由系统管理，网页无法覆盖其不透明部分，实际取色取决于 iOS 版本；需要没有浏览器工具栏的体验时，使用“添加到主屏幕”后启动的 Web App。

1. 电脑和 iPhone 连接同一个 Wi-Fi，在 Safari 打开受信任的地址，例如 `https://192.168.1.10:5188/`。
2. 双击画面显示界面，再点“启用手机体感”，在 iOS 弹窗中允许方向访问。
3. 保持初始姿态完成校准；体感连接成功后界面自动收起。让头部基本保持不动，再缓慢转动手腕观察反向补偿、下沉和失焦。需要调节或重新校准时，双击画面显示界面。
4. 需要沉浸显示时，在 Safari 分享菜单中选择“添加到主屏幕”，从主屏幕启动。

页面也支持重新校准和切换回手动模拟。若证书或权限不可用，可以继续查看画面和使用桌面/触屏手动模式。

体感、带手机外框的预览和无外框手动演示都采用可调的视角补偿。一侧整条竖边固定，另一侧交给透视计算，没有贴边约束，也不会按旋转后的包围盒重新拉满图片。体感与外框预览的图片仍以 1:1 转角反向旋转，体感角度限制在 ±80°；艺术翻转倍率和最大翻转只用于无外框的手动演示。

双击画面，再打开右上角调节面板，可调整“拉伸补偿”：默认 100%，0% 是无补偿的自然内翻，调高会恢复更多横向宽度。补偿强度独立于图片翻转倍率和失焦预设，换预设不会覆盖它；“还原”会恢复 100% 和默认 50 cm 透视距离。补偿后的观察角超过 45° 时逐渐限幅，避免大角度展开突然增大。较高强度仍可能让远侧超出屏幕并被裁切，100% 表示最高强度，不代表所有角度下严格的几何抵消。

透视距离按约 7 cm 的手机屏幕短边换算，用于调整近远边大小差异。默认补偿是视觉调节起点，尚未根据真实眼睛位置标定；没有头部或眼位追踪，因此仍是近似的正面观看效果。

## 桌面模拟

桌面端可水平拖动画面中的手机，或使用“左右倾斜”滑杆。页面提供演示播放、三个效果预设、空间效果开关、最大翻转/失焦调节和回到正面操作。左右转动时，自动选择能让画面向内翻转的左侧或右侧边缘作为固定轴。下沉距离由翻转角度自然决定，不再整体移动画面，以保证固定边缘始终贴在屏幕上。

初次打开和点击“还原”均使用“深邃”预设，默认失焦程度为 36 px。失焦范围为 0–120 px（以 390 px 屏幕宽度为基准），轻盈 / 平衡 / 深邃预设分别为 16 / 48 / 36 px。实际失焦随倾角增加；越模糊的区域越暗，固定侧保持清晰明亮，回正或将失焦设为 0 时恢复亮度。

`public/wallpaper.png` 是完整的静态锁屏原图，包含时间、天气和背景画面；图中的控件不可点击，只有外层原型控制面板可交互。

## 实现要点

- 传感器校准后的平面到当前屏幕旋转为 `inverse = A^T B`，其中 `A` 是当前姿态，`B` 是首次校准姿态。
- 从完整逆姿态的 `inverse * (0, 0, 1)` 提取水平角与仰角。图片只使用水平角绕本地 Y 轴旋转；观察点使用经过补偿强度缩减、平滑限幅的水平角与仰角。单独前后倾斜或面内旋转不会触发图片翻转。
- 左、右边缘铰链为 `P`，平面平移为 `P - R*P`，因此铰链上的整条边始终满足 `R*P + translation = P`。相机为 `Ry(compensatedYaw) * Rx(compensatedPitch) * (0, 0, distance)`，逐像素对有限刚性平面做射线求交。补偿强度改变相机位置，不直接横向缩放图片，不改变铰链和图片旋转角度。
- `compensation.ts` 将每轴输入限制在 ±80° 后乘以强度。补偿角绝对值 `a` 在 45° 以内保持线性，超过后使用 `45 + 20 * (1 - exp(-(a - 45) / 20))`，在连接处保持数值和斜率连续，并渐近 65°。100% 是可调的默认值，不是对实际人眼位置的测量结果。
- UI 平面始终与画布同宽同高，不随角度缩放；纹理只按未旋转时的平面尺寸做 `cover` 等比铺满，横向居中、顶部对齐。远侧投影位置由同一套透视公式计算，不添加远侧贴边约束，不对旋转后的画面做二次铺满。投影之外保留内部暗色空间，然后与图片一起做模糊。
- WebGL2 先把绕边缘旋转的图片与黑色内部空间合成到离屏纹理，再对完整画面做横向、纵向高斯后处理。模糊强度从固定轴向远侧递增，图片与黑色空间的交界也参与采样，因此边缘可以自然散入黑色区域；最终只在屏幕边界裁切。
- 每个方向使用 33 次采样，大半径根据采样间距读取预过滤的 mip 层，避免细节出现重复条纹；清晰侧始终读取原始分辨率。压暗在最后一次后处理按同一失焦梯度施加，同时作用于图片和黑色空间，不重复叠加。
- 视觉参数按约 390 CSS px 的画布宽度缩放，适配较小屏幕时保持深度和模糊的比例。
- 开发时修改 JavaScript/TypeScript 会整页刷新，使体感、WebGL 和动画循环一起使用新代码，避免界面更新而旧投影闭包继续运行；刷新后需重新启用体感并校准。CSS 修改仍可热更新。

## 检查

```bash
pnpm test
pnpm build
```

启动开发服务后，打开 `http://localhost:5188/tests/renderer-check.html` 可运行真实 WebGL 像素检查：不同画布比例下的方形标记是否符合刚性平面透视、模糊是否跨过图片边界、大半径是否扩大扩散范围、固定侧是否保持清晰、局部压暗是否随铰链方向翻转、零模糊是否精确还原，以及离屏纹理的尺寸更新与上下文恢复。该检查页不包含在生产构建中。

HTTPS 服务启动时使用 `https://localhost:5188/tests/renderer-check.html`。检查包含不同画布比例下的正面铺满、左右铰链完整贴边、无补偿时远侧自然收拢和暗色空间，以及等比纹理投影。实际 App 检查验证补偿相机与图片转角独立、体感与桌面预览采用相同补偿规则，以及调节补偿后确实重绘。另已模拟验证可见视口缩小、偏移、横竖屏、设置面板滚动和退出沉浸后的页面恢复；这些检查不等同于 iPhone 实机验收。

当前数学与效果测试共 28 项，含补偿变化时铰链全高固定、50% 补偿的镜像和投影宽度、连续限幅、单轴提取、非零初始姿态校准及失焦与亮度联动。检查页还包含 12 组通用渲染器的观察仰角与左右倾角组合，每组检查图片上、中、下部至少 6 个完整标记的投影边界；实际 App 集成检查覆盖手机传感器、补偿调节和三个预设下左右各 55° 的桌面预览。项目尚未在真实 iPhone 上完成本次补偿调整的实机验收。

无补偿场景的 24 组远边检查覆盖四种画布比例、左右 30° / 45° / 55°，验证远侧原图边缘出现在独立计算的内缩位置，屏幕远端露出暗色空间，同时固定侧整条边仍贴屏。

浏览器检查覆盖 375/390 px 竖屏与 812×375 横屏、授权拒绝/允许、HTTP 提示、单轴方向事件、左右铰链切换、预设、效果开关及演示播放/暂停。WebGL 像素检查验证了左右两侧在 15°、30°、45° 翻转时，固定边缘采样保持在原图同一位置；浏览器中没有发现运行错误。

全屏修正另在浏览器模拟中检查了 390×844 竖屏、844×390 横屏、缩小的可见视口、`pageshow` / 前台恢复、设置面板滚动及退出沉浸。页面、body、根节点与画布高度保持一致，画布不会被桌面 3D 容器定位；这些模拟不替代 iPhone 主屏幕 Web App 的实机验证。
