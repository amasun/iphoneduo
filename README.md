# Inside Motion Study

这是一个 React + TypeScript + Vite 的纯 WebGL2 视觉原型，用来测试“手机左右倾斜时，屏幕 UI 以一侧边缘为铰链反向旋转，并向屏幕内部下沉、逐渐失焦”的效果。只使用绕屏幕竖轴的旋转，前后倾斜和面内旋转不会单独改变画面。它使用 `DeviceOrientation` 读取真实手机姿态，也提供手动模拟；这不是头部追踪系统。

## 在线体验与部署

- 在线地址：[INSIDE](https://amasun.github.io/iphoneduo/)
- 源码仓库：[amasun/iphoneduo](https://github.com/amasun/iphoneduo)

在线版本由 GitHub Pages 提供受信任的 HTTPS，无需连接开发电脑的 Wi-Fi 或安装本地证书。iPhone Safari 打开后，双击显示操作界面，启用手机体感并允许方向访问；也可添加到主屏幕后打开。

推送到 `main` 后，GitHub Actions 会使用 Node.js 24 与项目指定版本的 pnpm 安装依赖、运行测试、构建并发布 `dist`。Pages 使用 GitHub Actions 作为部署来源。生产资源使用 `/iphoneduo/` 前缀，PWA 启动地址和作用域也跟随项目路径；本地开发仍从 `/` 访问。部署不需要额外配置密钥。

## 本地启动

在项目目录执行：

建议使用 Node.js 24 与 pnpm。

```bash
pnpm install
pnpm dev
```

桌面浏览器可打开 `http://localhost:5188/`。同一 Wi-Fi 下，手机 Safari 可以访问电脑的局域网地址，例如当前示例：

```text
http://192.168.1.10:5188/
```

`192.168.1.10` 只是本机当前示例，实际地址以电脑网络适配器显示的 IPv4 为准；可用 `ipconfig` 查看。电脑防火墙需要允许 Node/Vite 监听 5188 端口。

普通 HTTP 地址适合查看视觉和手动模拟。iPhone Safari 的方向传感器需要受信任的 HTTPS 环境；局域网 HTTP 页面不应当作为体感测试地址。

## iPhone HTTPS

本机已使用 mkcert 配置本地受信任证书，覆盖 `localhost`、`127.0.0.1`、`::1` 和 `192.168.1.10`。网站证书有效期至 2028-12-11。网站证书和私钥保存在已忽略的 `certs/`；根 CA 私钥由 mkcert 保存在系统用户目录中。

启动 `pnpm dev:https` 后，体验地址为 `https://192.168.1.10:5188/`。另外在一个终端运行 `pnpm dev:cert`，iPhone Safari 可打开 `http://192.168.1.10:5189/` 下载公开的根证书并查看安装步骤。证书下载服务仅提供说明页和 `inside-local-ca.cer`，不会开放任何目录或私钥。首次在 iPhone 安装后，还需要在「设置 → 通用 → 关于本机 → 证书信任设置」中开启完全信任。

先停止原来的 HTTP 开发服务，再启动 HTTPS 服务（两者默认使用同一个端口）。

```bash
pnpm dev:https
```

没有本地证书时，这个命令使用 Vite 的自签名证书。它可以用于查看页面，但 iOS 是否信任该证书、以及方向权限是否可用，都不保证。正式测试建议使用受信任的 HTTPS 证书。

项目已经支持以下证书文件：

```text
certs/dev.pem
certs/dev-key.pem
```

两者同时存在时，Vite 会直接读取它们；`certs/` 已被 `.gitignore` 忽略。可以用 `mkcert` 为本机地址生成证书：

```bash
mkcert -install
mkdir certs
mkcert -cert-file certs/dev.pem -key-file certs/dev-key.pem localhost 127.0.0.1 192.168.1.10
pnpm dev:https
```

如果局域网 IPv4 变化，需要用新的地址重新生成证书。为了让 iPhone 信任这套本地 CA，把 `mkcert` 生成的 `rootCA.pem` 传到 iPhone 并安装，然后在“设置 > 通用 > 关于本机 > 证书信任设置”中打开对该根证书的完全信任。只安装 `rootCA.pem`，绝不要把 `rootCA-key.pem` 传到手机或提交到仓库；证书私钥也不要提交。

## iPhone 操作

手机打开页面会自动进入沉浸模式，横屏打开也支持。默认只显示画面，双击画面显示操作界面，再次双击收起。显示后，右上角可打开效果调节，左上角可退出沉浸模式；电脑切换到手机尺寸预览时也会自动进入。单击、拖动、长按与双指操作不会触发界面切换。

沉浸画布覆盖浏览器允许绘制的完整区域，操作界面跟随可见视口，主屏幕 Web App 使用相同布局。背景按等比铺满、顶部对齐显示，屏幕较矮时优先保留原图顶部，将超出的下方内容裁掉；较窄时允许从左右裁切，不拉伸。转动时不会为了容纳整张图片而整体缩小，固定侧整条边保持贴屏，超出屏幕的内容由物理屏幕边界裁切。

全屏布局参考了 [Solo](https://solotilt.com/) 的视口处理：`html`、`body` 与画布都使用完整的大视口高度，画布直接固定到视口，安全区仅给操作控件留距离。此前只有固定定位的内部容器撑满，`body` 实测高度为 0；现在文档本身也覆盖画面，并移除沉浸模式继承的桌面 3D 容器。页面恢复、切回前台和尺寸变化都会更新视口位置。

主屏幕清单声明 `fullscreen`，同时保留 iOS 的 `black-translucent` 与 `viewport-fit=cover` 设置。iOS 会缓存已添加的 Web App 启动信息；更新后请删除旧的 INSIDE 主屏幕图标，在 Safari 重新打开 HTTPS 首页，再通过“添加到主屏幕”添加，若出现“作为 Web App 打开”选项则保持开启。仅刷新旧图标内的页面可能不会更新启动模式。

页面不再指定深黑色的浏览器主题，并用原图和灰蓝色背景填充可绘制区域。Safari 地址栏和工具栏由系统管理，网页无法覆盖其不透明部分，实际取色取决于 iOS 版本；需要没有浏览器工具栏的体验时，使用“添加到主屏幕”后启动的 Web App。

1. 电脑和 iPhone 连接同一个 Wi-Fi，在 Safari 打开受信任的地址，例如 `https://192.168.1.10:5188/`。
2. 双击画面显示界面，再点“启用手机体感”，在 iOS 弹窗中允许方向访问。
3. 保持初始姿态完成校准；体感连接成功后界面自动收起。让头部基本保持不动，再缓慢转动手腕观察反向补偿、下沉和失焦。需要调节或重新校准时，双击画面显示界面。
4. 需要沉浸显示时，在 Safari 分享菜单中选择“添加到主屏幕”，从主屏幕启动。

页面也支持重新校准和切换回手动模拟。若证书或权限不可用，可以继续查看画面和使用桌面/触屏手动模式。

体感、带手机外框的预览和无外框手动演示的屏幕内部采用同一套单轴投影：图片以 1:1 转角反向旋转，范围均为 ±80°，只保留一套可微调参数。一侧整条竖边固定，另一侧交给透视计算，没有贴边约束，也不会按旋转后的包围盒重新拉满图片。所有模式都忽略俯仰角。

双击画面，再打开底部右侧调节面板，可调整“拉伸补偿”：默认 60%，观察角按左右转角的 60% 计算。设为 100% 时，在 ±80° 范围内观察角等于实际左右转角，超过 45° 也不再压缩角度。0% 是无补偿的自然内翻，中间强度按比例缩减观察角。“还原”会恢复 60%、40 cm 观看距离以及 iPhone 14 Pro 的屏幕尺寸。较大角度会自然展开，并可能让远侧超出屏幕而被裁切。

沉浸模式的设置按钮位于底部右侧，紧凑面板从底部向上展开，只显示拉伸补偿、远侧收缩、开始失焦、透视距离和失焦程度，以及还原、关闭操作。面板外不加深色遮罩，点击外部或再次点击设置按钮即可关闭；启用体感与校准正面仍在画面底部操作。

配置、手动模拟和体感引导使用暗色毛玻璃。手机面板与浮动按钮共用透明底色和 18 px 背景模糊；桌面面板加深底色以保证浅色背景上的文字对比。手机调节面板最大宽 360 px，窄屏保留两侧 12 px 间距；每条滑杆具有 56 px 高触控区域和 24 px 滑块，浮动按钮为 48 px。横屏面板可内部滚动，小屏精简角度提示，避免底部操作溢出。

「远侧收缩」范围为 0–200%，默认 50%，用于单独调节近大远小：100% 为原来的距离透视；50% 减弱远侧收缩；0% 为平行投影，不再因深度缩小；200% 加强收缩。它不会改变图片的 1:1 反向转角、铰链或已填写的 40 cm 实际观看距离。横向展开程度仍由「拉伸补偿」控制。两项均为视觉调节，不代表实测眼位。

内部固定按 iPhone 14 Pro 校准：依据 [Apple 屏幕规格](https://support.apple.com/en-us/111849) 的短边 1179 像素与 460 ppi，计算发光区域短边约为 `1179 / 460 × 2.54 = 6.51 cm`，界面不再提供屏幕尺寸滑杆，旧版保存的自定义尺寸也恢复为此值。默认观看距离为 40 cm；需要量取双眼之间到屏幕中心的实际距离后调整。旧版保存的 50 cm 会在首次加载新版时更新为 40 cm；其他距离保留，之后重新选择 50 cm 也能正常保存。

「透视距离」自动保存在当前设备和浏览器中，刷新后保留；其他视觉调节仍在刷新后恢复默认值。「还原」会恢复上述默认值。手机端使用完整物理屏幕的 CSS 像素尺寸换算，浏览器工具栏收缩或横竖屏切换不会改变每厘米的像素比例；桌面虚拟手机使用预览画布尺寸。测试其他型号时，需要在代码中更新屏幕尺寸常量。

投影假定校准时眼睛正对屏幕中心，且头部和手机中心基本不平移。页面不会自动测量人眼距离，也没有头部或眼位追踪；忽略俯仰的单轴模式仅校正左右旋转。

## 桌面模拟

桌面外框使用原始 iPhone 17 Pro Max glTF 三维模型，由 Three.js / GLTFLoader 加载。机身几何、PBR 材质参数及两张贴图保留，环境光照提供金属反射；实时画面使用独立显示层接入屏幕，不替换原有机身或屏幕材质。模型与原始材质文件位于 `public/models/iphone-17-pro-max/`，与用户提供的源文件逐字节一致。手机无边框沉浸模式不加载模型资源。

This work is based on "iPhone 17 Pro Max" (https://sketchfab.com/3d-models/iphone-17-pro-max-87fc1df741384124a8ce0226d2b2058d) by MajdyModels (https://sketchfab.com/MG990) licensed under CC-BY-4.0 (http://creativecommons.org/licenses/by/4.0/). 本项目添加独立实时屏幕显示层、交互姿态与环境光照；原始许可附于模型目录的 `license.txt`。

桌面端上下左右拖动可自由浏览真实三维机身：左右旋转无角度上限，可连续绕圈；上下俯仰限制在 ±10°，查看机身时保持接近正立。“左右倾斜”滑杆覆盖 -180° 至 180° 的一整圈，拖动模型可跨过滑杆端点继续旋转；“回到正面”同时复位两个方向。屏幕内部的单轴视错觉仍限制在 ±80°，手机体感忽略俯仰；浏览机身的垂直角度不参与屏幕内的失焦与补偿计算。页面继续提供演示播放、失焦调节、空间效果开关及补偿与距离调节。

只保留一套参数，初次打开与点击“还原”均使用：开始失焦 5°、失焦程度 36 px、拉伸补偿 60%、远侧收缩 50%、观看距离 40 cm、屏幕短边 6.51 cm。失焦仍可在 0–120 px 内调节（以 390 px 屏幕宽度为基准）。实际失焦随倾角增加；越模糊的区域越暗，固定侧保持清晰明亮，回正或将失焦设为 0 时恢复亮度。

`public/wallpaper.png` 是完整的静态锁屏原图，包含时间、天气和背景画面；图中的控件不可点击，只有外层原型控制面板可交互。

## 实现要点

- 传感器校准后的平面到当前屏幕旋转为 `inverse = A^T B`，其中 `A` 是当前姿态，`B` 是首次校准姿态。
- 从实际相对姿态 `transpose(inverse) = B^T A` 的屏幕法线提取水平朝向，再取反作为图片转角。先分离实际姿态的水平角，可以避免已向左或向右转动时，俯仰变化串入水平角。俯仰角与面内旋转不参与图片变换或观察点补偿；纯俯仰、以及保持水平朝向时的局部俯仰变化均不改变渲染结果。
- 左、右边缘铰链为 `P`，平面平移为 `P - R*P`，因此铰链上的整条边始终满足 `R*P + translation = P`。相机为 `Ry(compensatedYaw) * (0, 0, distance)`，高度固定为 0，逐像素对有限刚性平面做射线求交。补偿强度改变相机位置，不直接横向缩放图片，不改变铰链和图片旋转角度。
- `compensation.ts` 将输入限制在 ±80° 后乘以强度，范围内不做非线性压缩。100% 时平面和观察点使用相同左右转角，俯仰始终为 0。`viewingCalibration.ts` 按「观看距离 / 实际屏幕短边 × 参考短边像素」换算透视距离，并校验保存的校准值。
- 远侧收缩强度为 `k`，射线原点为玻璃上的像素 `Q`，方向为 `k*Q - camera`。`k>0` 等价于把虚拟眼点置于 `camera/k`，`k=0` 精确退化为平行投影；仍对刚性平面求交，不单独拉伸某条边。40 cm / 6.51 cm 对应正面水平视野约 9.3°，默认 `k=0.5` 的等效渲染视野约 4.7°；这与手机 ±80° 的旋转范围不同。该调节改变虚拟投影，桌面外框仍按实际观看距离投影。
- UI 平面始终与画布同宽同高，不随角度缩放；纹理只按未旋转时的平面尺寸做 `cover` 等比铺满，横向居中、顶部对齐。远侧投影位置由同一套透视公式计算，不添加远侧贴边约束，不对旋转后的画面做二次铺满。投影之外保留内部暗色空间，然后与图片一起做模糊。
- WebGL2 先把绕边缘旋转的图片与黑色内部空间合成到离屏纹理，再对完整画面做横向、纵向高斯后处理。模糊强度从固定轴向远侧递增，图片与黑色空间的交界也参与采样，因此边缘可以自然散入黑色区域；最终只在屏幕边界裁切。
- 每个方向使用 33 次采样，大半径根据采样间距读取预过滤的 mip 层，避免细节出现重复条纹；清晰侧始终读取原始分辨率。压暗在最后一次后处理按同一失焦梯度施加，同时作用于图片和黑色空间，不重复叠加。
- 视觉参数按约 390 CSS px 的画布宽度缩放，适配较小屏幕时保持深度和模糊的比例。
- 开发时修改 JavaScript/TypeScript 会整页刷新，使体感、WebGL 和动画循环一起使用新代码，避免界面更新而旧投影闭包继续运行；刷新后需重新启用体感并校准。CSS 修改仍可热更新。

## 检查

```bash
pnpm test
pnpm build
```

启动开发服务后，打开 `http://localhost:5188/tests/renderer-check.html` 可运行真实 WebGL 像素检查：不同画布比例下的方形标记是否符合刚性平面透视、模糊是否跨过图片边界、大半径是否扩大扩散范围、固定侧是否保持清晰、局部压暗是否随铰链方向翻转、零模糊是否精确还原，以及离屏纹理的尺寸更新与上下文恢复。该检查页不包含在生产构建中。

HTTPS 服务启动时使用 `https://localhost:5188/tests/renderer-check.html`。检查包含不同画布比例下的正面铺满、左右铰链完整贴边、无补偿时远侧自然收拢和暗色空间，以及等比纹理投影。实际 App 检查验证补偿相机与图片转角独立、体感与桌面预览采用相同补偿规则，以及调节补偿后确实重绘。另已模拟验证可见视口缩小、偏移、横竖屏、设置面板滚动和退出沉浸后的页面恢复；这些检查不等同于 iPhone 实机验收。

当前数学与效果测试共 36 项，含真实角度下的投影往返与方形比例恢复、校准尺寸换算、俯仰不串入水平转角、非零姿态校准、铰链全高固定及失焦与亮度联动。检查页还包含 12 组通用渲染器的观察仰角与左右倾角组合，每组检查图片上、中、下部至少 6 个完整标记的投影边界；实际 App 集成检查覆盖无框手动与真机的相同转角、观看距离校准、固定屏幕尺寸、远侧收缩滑杆重绘与还原、固定左右朝向时改变俯仰，以及 ±80° 范围内的观察角。新增像素检查覆盖远侧收缩 0%、50%、100%、200% 的左右投影、正面不变及 resize 后状态保留；手动外框、无框和模拟体感各验证 4 个收缩强度。通用渲染器保留仰角测试能力，产品体感不使用仰角。项目尚未在真实 iPhone 上完成本次调整的实机验收。

三维手机检查使用独立投影计算，在正面、左右 60° / 80° 下采样 20 个屏幕色块，并验证实时纹理更新、源画布增大后的重新分配、视口尺寸变化及中性灰色还原。桌面浏览器还检查了三维上下文恢复、退出/进入沉浸模式和实时渐进模糊；手机模拟视口确认只加载无边框画面，不下载 Three.js 或模型资源。

无补偿场景的 24 组远边检查覆盖四种画布比例、左右 30° / 45° / 55°，验证远侧原图边缘出现在独立计算的内缩位置，屏幕远端露出暗色空间，同时固定侧整条边仍贴屏。

浏览器检查覆盖 375/390 px 竖屏与 812×375 横屏、授权拒绝/允许、HTTP 提示、单轴方向事件、左右铰链切换、参数调节、效果开关及演示播放/暂停。WebGL 像素检查验证了左右两侧在 15°、30°、45° 翻转时，固定边缘采样保持在原图同一位置；浏览器中没有发现运行错误。

全屏修正另在浏览器模拟中检查了 390×844 竖屏、844×390 横屏、缩小的可见视口、`pageshow` / 前台恢复、设置面板滚动及退出沉浸。页面、body、根节点与画布高度保持一致，画布不会被桌面 3D 容器定位；这些模拟不替代 iPhone 主屏幕 Web App 的实机验证。

三维浏览的集成检查通过真实指针事件验证累计 480° 水平旋转、反向旋转、±10° 俯仰边界、边界处继续水平旋转与反向俯仰，以及双轴回正；原有手机体感单轴与透视检查继续保留。

桌面采用单屏 dashboard：整屏采用纯白背景，三维手机始终位于视口中央，没有独立预览卡片边框。旋转滑杆、播放和回正操作悬浮在底部中央；右上角提供「iPhone 预览」与调节按钮，PC 预览默认展开暗色毛玻璃参数面板，可通过调节按钮或关闭按钮收起，面板底部默认显示通往线上 HTTPS 版本的二维码，与参数共用同一块毛玻璃背景；小窗口下在面板内部滚动。二维码为本地静态 SVG，不依赖外部图片服务，仅桌面预览显示。操作说明默认折叠，底部独立页脚显示「Design by Artgineer」及其小红书主页链接，并保留模型来源与许可署名。手机初始不显示控件，双击后提供简短引导和原有底部毛玻璃调节面板。

PC 预览左上角提供 EN / 中文切换，选择保存在当前浏览器中，默认中文。英文覆盖参数、体感状态、二维码提示、使用说明、无障碍标签和页面标题；切换不会重新创建画布或重置参数、旋转与播放状态。PC 无框预览也可切换语言。手机按原有体验保持中文和默认隐藏控件。
